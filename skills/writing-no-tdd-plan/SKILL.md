# 编写轻量实现计划

## 边界与模式

为无需详细设计的任务生成可执行计划。仅在用户明确要求时使用；模式由用户决定，技能不得判断复杂度。

| 用户指定 | 模式 | 事实源 |
| --- | --- | --- |
| `L0`、无需核心认知 | L0 | 任务事实摘要 |
| `L1`、需要核心认知 | L1 | 独立核心认知文档 |
| `L2`、复杂任务 | 不支持 | 完整设计和 `writing-plans` 流程 |

用户未指定或表达含糊时，只问：

> "本次轻量计划使用 L0 还是 L1？"

即使用户要求“自己决定”、时间紧急或模式看起来明显，也不得代选、默认、改判或升级。用户选定后声明：

> "我正在使用 writing-no-tdd-plan 技能编写轻量实现计划。"

硬规则：

- L0 不创建核心认知；L1 必须先创建或更新核心认知。
- L0、L1 均不要求、创建或引用 Foundation Gate、详细设计及其配套产物。
- 只消费已确认事实；不得发明需求、行为、接口、状态或存储规则。
- 计划阶段不得实现。



| 模式 | 前置事实 |
| --- | --- |
| L0 | 计划头部记录目标、范围、现状证据及来源锚点、约束、不做事项、验收标准。缺少影响行为的事实时停止询问，不得推测。 |
| L1 | **REQUIRED SUB-SKILL:** Use `core-principle` before planning. 核心认知必须达标；关键事实有来源或 `待确认`；阻塞项先收敛。计划只按章节引用，不复制稳定事实。 |

## 计划准备

定义任务前：

1. 核对真实文件、测试、现有模式和仓库状态。
2. 列出新建、修改、测试文件及职责。
3. 按依赖顺序拆分独立、可验证的任务。
4. 区分编码和非编码任务，使用对应模板。

计划必须给出准确路径、具体动作和验证语义；不得写实际实现代码、测试代码、具体测试命令、验证命令或提交命令。

已执行、执行中或已被下游消费的计划只能新增增量计划并更新 `PLAN_CHANGELOG`，不得覆盖原计划。

## 计划头部

`PLAN_PATH` 必须以以下信息开头：

```markdown
# [功能名称] 轻量实现计划
> **计划模式：** L0 / L1
> **事实源声明：** [L0：任务事实摘要；L1：核心认知文档绝对路径及章节]
> **详细设计声明：** 本计划不依赖详细设计，不得扩展已确认事实。

- **目标：** [可观察结果]
- **范围：** [允许修改的范围]
- **不做事项：** [明确排除项]
- **验收标准：** [可验证完成条件]

**代码仓库与分支：**
- 代码仓库：[仓库本体绝对路径]
- 开发目录：[日常代码读写绝对路径]
- 开发分支：[分支名]
```

L0 紧接头部写“任务事实摘要”；L1 写 `CORE_COGNITION_PATH` 绝对路径和引用章节。不得伪造详细设计路径。

## 任务顺序闸门

计划必须包含：

```markdown
### 0. 任务顺序闸门（强制）

- [ ] 当前任务所有步骤完成后，将当前任务所有复选框标记为 `[x]`。
- [ ] 当前任务未标记完成前，不得开始下一个任务。
- [ ] 编码任务必须先完成实现、规范审查、问题修复和提交，才能标记完成。
```

## 编码任务模板

每个编码任务必须保留实现、代码和测试审查、问题修复、逐任务提交。

````markdown
### 任务 N：[组件名称]
**事实来源：** [L0 事实摘要条目；或 L1 核心认知章节]
**涉及文件：**
- 新建：`exact/path/to/file`
- 修改：`exact/path/to/existing:line`


- [ ] **步骤 1：[具体实现动作]**
- [ ] **步骤 2：按仓库规范审查代码，并修复问题**
读取并应用当前仓库的代码。修复全部问题后再提交。

- [ ] **步骤 3：提交当前任务**
只提交当前任务相关改动，不写具体提交命令。

- [ ] **最终步骤：标记任务 N 已完成，再进入任务 N+1**

**预期验证语义：**
- [行为、边界或异常语义的具体完成条件]
````



## 禁止项

- 禁止 `TBD`、`TODO`、`implement later`、`fill in details`、“类似任务 N”。
- 禁止无具体字段、条件和错误语义的“添加校验/处理异常”。
- 禁止只写“做什么”不写“怎么做”、复制 L1 核心认知、把 L0 摘要伪装成完整核心认知。


## 完成检查
- 模式未改判；路径和事实源符合对应契约；`PLAN_PATH` 是唯一入口。
- 计划不依赖详细设计、不扩展事实、无占位符；每个任务可执行、可验证。
- 编码任务保留实现、审查、修复、逐任务提交；非编码任务未误套这些闸门。
